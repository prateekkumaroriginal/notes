What the new commit fixes

The earlier head ce0dc226ae62 set dmValidations to null, then unlocked broadcast and followers in the same turn. sendMessage read dmValidations.minTipKeys whenever a custom tip amount was set. Opening a mailing list did not clear that amount. Enter threw.

The minimum tip now goes through dmValidations?.minTipKeys, and falls back to minimumTip when permissions are null. requestParamsofBroadcast calls closeTipPopup before history loads, so the custom amount is gone. The emoji button uses areMessageActionsLocked too.

If generateGroudId rejects, or the response has no group id, both loaders stop, permissionsFailed stays true, and dmValidations is cleared. The same lock applies when the receiver id is missing. Retry is still checkNewUserValidation. Send stays disabled until that call returns status: true.

Inbox refetch

Sending on an existing direct message used to call getUserChatLogs just to move that row. updateUserList now rewrites the matching row's preview, last_message.timeStamp, and updated_at. It refetches only when that group id is missing from every tab.

An incoming message on the open thread updates the transcript and the direct-message tabs, and skips getUserChatLogs. A message for a different thread still refetches the inbox. History keeps its own cancel subject, so that refetch cannot drop the open transcript.

A mailing list you just sent still refetches when the send socket reports status. An incoming mailing-list message, while that list is open, updates the transcript and leaves the left-hand row where it was. The row already exists in the broadcast tab, so the new "missing from every tab" check does not refetch it.
