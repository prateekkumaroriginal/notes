JavaScript field note 01

One task, three async styles

Callbacks, Promises, and async/await solve the same problem: how to continue after work finishes later. The syntax changes. The event loop does not.

Start with the mental model

JavaScript starts a task, keeps running other code, then handles the result when it is ready. Each style gives that final step a different shape.

start task → keep running → handle result

Callback

Pass the next step as a function.

Promise

Receive an object representing a future result.

Async / await

Pause one async function until that Promise settles.

key

await pauses only the current async function. It does not block the JavaScript thread.

01. Callbacks

A callback is a function passed to another function to be called later. The convention in Node.js is (error, result).

Good fit: event handlers, streaming APIs, and simple one-off continuations.

Pressure point: dependent steps create nesting, and every layer must remember to forward errors exactly once.

02. Promises

A Promise is a value with three possible states: pending, fulfilled, or rejected. Once settled, it never changes state again.

watch

Return the next Promise from .then(). Without return, the chain cannot wait for it or catch its rejection.

03. Async / await

async makes a function always return a Promise. await unwraps a fulfilled value or throws the rejection, so ordinary try/catch/finally works.

This reads top to bottom, but the operations above are still sequential. The second request starts only after the first resolves because it needs user.id.

Sequential or concurrent?

The most common async/await performance mistake is waiting in sequence when tasks are independent.

Combinator Settles when Use it for
Promise.all All fulfill, or one rejects Every result is required
Promise.allSettled Every task settles Collecting successes and failures
Promise.any The first task fulfills Taking the first successful result
Promise.race The first task settles Timeouts and literal races

Rules worth remembering

  1. Use async/await by default for Promise-based code.

    Reach for direct Promise chains when they make a transformation pipeline clearer.

  2. Return or await every Promise you depend on.

    A floating Promise can reject outside your error handling and finish after its caller.

  3. Run independent tasks together.

    Start them before awaiting, usually with Promise.all.

  4. Catch errors where you can add meaning or recover.

    Otherwise, let the rejection travel to a caller that can make the decision.

  5. Cancellation is separate.

    A Promise has no built-in cancel method. APIs such as fetch use AbortController.

Quick check

Test the mental model, then reveal the answer.

Does await block the whole JavaScript thread?

No. It suspends the current async function. Other queued work can continue.

What does an async function return?

Always a Promise, even when you return a plain value.

When should two calls go into Promise.all?

When the calls are independent and you require both results.
