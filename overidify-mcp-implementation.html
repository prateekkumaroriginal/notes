How the Overidify MCP server works

A Chrome extension can't listen on a port, so Overidify can't host an MCP server by itself. This post covers the local helper that hosts it, how tool calls reach the extension, how setup works without the source code, and how it was tested.

The extension can't be the server

MCP clients connect to a server in one of two ways. They start it as a process, or they connect to it over HTTP. A Manifest V3 extension supports neither. Its service worker can't open a listening socket, other programs can't start it, and Chrome stops it when it's idle.

Chrome does offer native messaging. An extension can ask Chrome to start a registered program and exchange messages with it over stdin and stdout. Overidify uses that. When you turn on the MCP server, the service worker calls chrome.runtime.connectNative('com.overidify.mcp'). Chrome starts a small Node.js helper, and the helper serves http://127.0.0.1:47821/mcp.

An open native port also keeps the service worker running. Agents don't wait for it to wake up.

Architecture

The helper stays thin

The helper has no rule logic. When the service worker connects, its first message carries the port, the token, the extension version, the server instructions, and the tool definitions. The helper serves whatever tools it receives and forwards each call.

New or changed tools therefore ship with the extension, and the helper doesn't need reinstalling. Both sides exchange a bridge protocol number. If an update changes the messages themselves, the Agents page asks you to run setup again.

src/lib/mcp-protocol.ts 
type ExtensionToHostMessage =
  | { type: 'start'; protocol: number; port: number; token: string; version: string; instructions: string; tools: McpToolDefinition[] }
  | { type: 'result'; id: number; result: McpToolResult }

type HostToExtensionMessage =
  | { type: 'status'; protocol: number; state: 'listening'; url: string }
  | { type: 'status'; protocol: number; state: 'error'; message: string }
  | { type: 'call'; id: number; name: string; arguments: Record<string, unknown> }
  | { type: 'chunk'; id: number; index: number; total: number; data: string }

The native messaging bridge

Each native message is a 4-byte little-endian length followed by UTF-8 JSON. The helper encodes and decodes that framing itself. Its reader handles messages split across pipe reads.

Chrome rejects any message from a native program larger than 1 MB. A Network Rule's mock body can be bigger than that. So the helper measures each message's UTF-8 size before sending it. Messages under the limit go as they are. Larger ones are split into 256K-character chunks, which stay under 1 MB even when every character takes three bytes, and the extension reassembles them by call ID.

src/lib/mcp-protocol.ts 
export function splitNativeMessage(message, id, size = NATIVE_CHUNK_SIZE) {
  const text = JSON.stringify(message)
  if (new TextEncoder().encode(text).length <= NATIVE_MESSAGE_LIMIT) return [message]
  const total = Math.ceil(text.length / size)
  return Array.from({ length: total }, (_, index) => ({
    type: 'chunk', id, index, total, data: text.slice(index * size, (index + 1) * size),
  }))
}

Each call the helper forwards waits at most 60 seconds for a result. When the extension disconnects, Chrome closes the helper's stdin and the helper exits, which also closes any open requests.

One tool call, end to end

Agents get the same checks as Settings

Each tool's arguments are a strict zod object, and the tool's published input schema is generated from that same object. What an agent reads in tools/list always matches what the server enforces. Strict objects reject unknown keys, so a typo such as enable for enabled fails loudly instead of being ignored.

src/lib/mcp-tools.ts 
export const MCP_TOOLS = (Object.keys(RUN) as ToolName[]).map(name => {
  const inputSchema = z.toJSONSchema(RUN[name].input, { io: 'input' })
  delete inputSchema.$schema
  return { name, ...DESCRIPTIONS[name], inputSchema }
})

After the arguments pass, the rule goes through the same draft schemas and normalization as the Settings forms. Field paths in errors use the tool's names, like websites and headers.0.value, so the agent can fix its call. The zod/mini build has no default error messages, so the parser loads the English locale. Without it, every error would read "Invalid input".

Saving

updateSavedRules() reads, changes, and writes while holding both storage locks. An agent and an open Settings tab can't overwrite each other.

Activating

chrome.runtime.sendMessage never reaches its own sender, so the worker passes in an activate() function that runs the header sync and the network rule sync directly.

Updating

update_rule merges the given fields over the saved rule. It rejects fields from another rule type and keeps Switch option IDs when names match, so the selected option survives an edit.

Reporting

Results say whether the change is active, which tabs need a reload, or that it saved but Chrome didn't confirm it. An agent never reports success that didn't happen.

The HTTP endpoint

The helper implements the part of Streamable HTTP that tools need, without the MCP SDK. The whole helper builds to one 8 KB file with no dependencies, which keeps the setup file small and simple to install.

  • Methods: initialize, ping, tools/list, and tools/call. Batches work.
  • Every response is plain JSON. Notifications get 202, and GET gets 405 because there's no event stream to open.
  • Protocol versions 2025-11-25, 2025-06-18, 2025-03-26, and 2024-11-05.

The server checks every request before any tool runs. The checks are ordered from cheapest to most specific:

The server also binds only to 127.0.0.1, and the native host manifest allows only Overidify's extension ID to start the helper.

Setup without the source code

Chrome starts only native programs registered on that computer, so each machine needs a one-time setup. The extension builds the setup file itself, from two bundles that ship inside it:

globalThis.__overidifyMcpSetup = { extensionId, host }Added by the Agents page. host is the helper's source.
mcp/install.mjsThe installer, built for Node 20 and shipped in the extension.

The page fetches both bundles from its own package, joins them, and downloads overidify-mcp-setup.mjs. Running it with Node does three things:

Copy

Puts the helper in a user data folder, so it keeps working if the download is deleted.

Wrap

Writes a launcher that runs the helper with the absolute path of the Node that ran setup. Chrome doesn't use your shell's PATH, and this keeps nvm installs working.

Register

Writes the host manifest for each Chrome, Chromium, Edge, Brave, and Vivaldi profile it finds. On Windows it writes registry keys. Extension IDs from earlier runs are kept.

Meanwhile the Agents page shows that setup is needed and quietly retries the connection every two seconds. The status stays steady during retries, and once setup finishes the server starts without a Retry click. The setup prompt on that page relies on this. The agent runs the setup file, waits for the server to answer, then adds itself.

One server for every agent

Claude Code, Codex, and Cursor all connect over Streamable HTTP and can send a fixed Authorization header. One server works for all three. Only the config format differs, so the Agents page has a tab for each.

Each CLI was tested against the real server:

  • Claude Code 2.1.329 reported Connected in claude mcp list. It first sends a server/discover probe, gets method not found, and falls back to initialize.
  • Codex CLI 0.171.0 sent the token through http_headers in config.toml, then initialized and listed the tools.
  • Cursor's CLI agent listed all seven tools with their arguments from mcp.json.

Limits

  • The helper needs Node.js 20 or newer. Removing that would mean shipping a compiled helper for each operating system.
  • Setup has run for real only on Linux. The macOS and Windows paths are covered by unit tests.
  • No real agent has run the setup prompt from start to finish yet. The Cursor editor is untested; Cursor's CLI was tested.
  • Each browser profile with MCP on needs its own port.
