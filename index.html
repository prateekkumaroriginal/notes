What each PR gets right

PR 10823

  • The explicit Angular function types make invalid return values fail close to the guard declaration.
  • Injector-scoped flags preserve the lifetime model of the original root guard services.
  • The public initializer helper reads like Angular configuration, not token plumbing.
  • The permission guard migration stays close to the old implementation, which lowers semantic drift.

PR 10824

  • The NgRx selector already replays current store state, so the extra guard-owned BehaviorSubject is unnecessary.
  • The common can-deactivate guard no longer imports a constant from the Messages feature.
  • The hydration commit removes the incompatible router option at the same time it enables hydration.
  • The final implementation is shorter without changing the route table or public guard decisions.

Commit history matters

PR 10823 has a contradictory intermediate commit

Commit 02aa694c2b enables client hydration while RouterModule.forRoot still uses initialNavigation: 'enabledBlocking'. Angular 21 includes an explicit development-mode warning for this combination. The next commit fixes it, so the final head is sound. A squash merge avoids retaining that midpoint. PR 10824 keeps its first commit internally consistent.

Production-optimized builds remove Angular's development assertion, which is why QA SSR can still return HTTP 200 for the intermediate commit. Development-mode validation is the relevant check here.
