Prove SSR from the response body

A page loading in Chrome is not enough. An unapproved host can quietly receive the CSR shell with HTTP 200. Inspect the HTML and server output.

  • Home and login return HTTP 200. Test / and /auth/login with the expected Host header.
  • <app-root> contains rendered markup. An empty root is a CSR fallback, not a pass.
  • PrimeNG theme CSS is in the HTML. Find style elements with data-primeng-style-id. The verified build emitted four.
  • Use one route that was not prerendered. A creator profile is a good live-SSR check.
  • Unknown routes return 404. Do not accept a 200 blank shell for a garbage path.
  • Server output stays clean. There must be no is not allowed, Angular runtime error, or unhandled rejection.
  • Browser hydration preserves the page. Home and login remain populated after JavaScript starts, with no flash to an empty layout.

PrimeNG is the visual regression gate

PrimeNG moved from saga-blue CSS files to Lara styled mode and renamed the classes used by the application's overrides. Check behavior and appearance together.

Custom MultiSelect

  • Open the overlay. It has the expected dark tenant colors, rounded shape, spacing, and scroll container.
  • Search from the custom header. Filtering updates options and does not clear selected values.
  • Select all and clear all. The circular checkbox changes state and option selection matches the control value.
  • Select individual options. Selected rows and checked boxes are visibly distinct.
  • Remove a chip. The times-circle icon is visible and removes only that value.
  • Test both display modes. Exercise chip and comma-separated labels.
  • Use the custom footer. Cancel, confirm, and any feature-specific custom action are visible, themed, and clickable.
  • Use card view at three widths. Check desktop, tablet, and phone layouts for option cards and checkbox positioning.

Start with dynamic forms, then repeat on the song, podcast, item, video, and album portfolio editors. Also check Create Plan and discount-code forms.

Carousel

  • Image overlay and image overlay v2. Previous and next controls appear outside the image at desktop width and remain reachable on mobile.
  • Restricted-content and alert modals. Arrows retain their background, size, contrast, and click target.
  • Reels mobile view. The carousel list does not inherit an unwanted transform and swiping still changes the reel.
  • Circular and autoplay modes. Where enabled, wrapping and timed movement still work without duplicating or skipping items.

Build and render one white-label tenant

  • Generate in an isolated or disposable working tree. Do not commit generated tenant files or environment data with this release.
  • The generated builder remains application. It must not switch to the new @angular/build package during this hop.
  • The generated styles contain no primeng/resources paths. PrimeIcons stays.
  • The QA tenant build succeeds on Node 20.19.6. Use the same 10 GB heap as TopFans.
  • Request SSR with the tenant's real host. The response has populated app markup and PrimeNG style tags, with no host-allowlist error.
  • Branding survives hydration. Logo, title, theme colors, login, and cover-page behavior stay tenant-specific.
  • Repeat the MultiSelect and Carousel spot checks. Tenant variables must override Lara without losing contrast or control states.

Known noise and deliberate holds

  • Karma has zero specs. ng test --watch=false compiles and Chrome reports 0 of 0 SUCCESS, but the command may still exit 1.
  • Full lint exhausts the heap. It ran out of memory even at 10 GB. Targeted lint still reports existing prefer-standalone findings because this release keeps NgModules.
  • Serverless is not a gate. Do not migrate or build the webpack serverless target for this release.
  • Control-flow syntax is unchanged. The optional @if and @for migration was declined.
  • Zone.js and dynamic platform bootstrap remain. Their Angular 20 deprecation warnings do not mean this release should rewrite bootstrap.
  • ngx-toastr and ngx-stripe remain on their existing majors. Their next majors would pull Angular 21 or a Stripe.js major into this release.
