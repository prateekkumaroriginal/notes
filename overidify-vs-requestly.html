Overidify and Requestly

Both Chrome extensions can give an app a mock API response while Chrome's Network tab shows the server response. Requestly adds more rule types and execution feedback. Overidify already has a DevTools panel that captures API requests and opens a new Network Rule.

Updated 2 November 2026Chrome extensions only

Which version does this compare?

This note checks Overidify main at commit 20d17b0, dated 1 November 2026. Requestly findings use its official docs and public extension source. These are code and document checks, not a test of installed release ZIPs.

This main version includes request capture and rule creation from DevTools. Treat both as existing features when choosing the next work. The stable ZIP was not retested for this note.

Keep the three views separate

Native Network response
What Chrome's built-in Network tab displays. It records real network activity. A mock returned by page JavaScript can differ from this response.
Mock response
The body, status code, and headers supplied to the app. In Overidify, a Network Rule defines this response.
Extension panel
A separate tab inside DevTools. Each extension controls its own panel. A panel can list requests without changing Chrome's native Network tab.

Follow one API request

The server normally returns status 200 with Alice's data. The selected mock response returns status 500 with an error message. Choose whether the real request runs.

The extension calls the server, then gives the app the mock response. The real call can still change server data.

Both extensions wrap the page's fetch and XMLHttpRequest APIs. A wrapped call can return a different response to JavaScript after a real request completes. Requestly also supports a static response without a server call. See Requestly's native Network limitation and its fetch wrapper.

Compare the DevTools panels

Overidify's panel reads Chrome's captured request data. It can open the response in a new Network Rule. That capture can contain the server response even when the app received a mock.

Headers use a different path

Overidify's Header Rules and Switch Rules use Chrome's browser-level header rules. They change outgoing request headers. The response wrapper is a separate mechanism.

Requestly also uses browser-level header actions. It supports removing headers and changing live response headers. Overidify currently sets request headers and supplies headers as part of a mock response.

A mock response header returned to JavaScript does not provide a general browser-level CORS override. It also cannot set browser cookies. Do not assume that every header change has the same Network display behavior as a response-body mock. Requestly specifically warns that response-header changes may remain invisible there.

Source: Overidify's header rules, Requestly's header actions, and the display warning. Exact native header rendering still needs a test of each operation.

Where Overidify still has gaps

The main gaps are more precise matching, changes to live traffic, and clear execution feedback.

Requestly also documents browser bug recordings, JS/CSS insertion, and automation integration. Its store listing provides a simpler installation path than Overidify's ZIP and Load unpacked steps.

What I would improve first

  1. Show the matched Rule, server result, and mock response together. Mark a bypassed call clearly. Extend the existing capture panel.
  2. Add request target patterns and selected-query matching. Keep website scope separate. Add GraphQL operation conditions.
  3. Add delay, deliberate blocking, and request-header removal. Keep a transport failure separate from an HTTP error response.
  4. Add host switching and controlled changes to live response data.
  5. Add groups for complete test scenarios. Improve installation before building a cloud collaboration service.

These are product recommendations. They are not measured user demand or delivery estimates. The first changes fit the current response-mocking engine.

Evidence and limits

The scope is the Chrome extension and its documented account workflows. Requestly's desktop proxy, native-app interception, hosted mock servers, and API Client test runners are separate products. They are excluded from the gap list.

This review does not confirm that every Requestly panel response is the final mock seen by the app. It also does not establish an extension environment-variable system, bandwidth controls, or built-in Git history. Exact paid quotas remain unverified.
