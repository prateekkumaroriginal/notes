Props, Children, Composition, and Component Purity

React components stay reusable when data flows in through props, layouts accept nested content, and rendering remains predictable.

The mental model

A component is a JavaScript function that returns JSX. Its inputs describe what it should display.

Props

Named inputs passed by a parent.

Children

Content placed between component tags.

Composition

Building features from smaller components.

Purity

Same inputs, same rendered result.

Props are component inputs

A parent passes props with JSX attributes. React gathers them into one object and supplies that object when it calls the component. Props may hold strings, numbers, booleans, objects, arrays, functions, or JSX.

  • Quoted attributes are strings.

    name="Mina" passes the string "Mina".

  • Curly braces evaluate JavaScript.

    isOnline={true} passes a boolean, not the string "true".

  • Props are read-only.

    A child must not assign to a prop. If an interaction should change data, the parent can pass state and an event handler.

Children is a special prop

Content nested inside a component becomes its children prop. A wrapper can decide where that content belongs without needing to know what the content is.

Children can be text, elements, components, lists, or nothing. A self-closing component such as <Panel /> has no nested children. Use named props when the component needs several distinct content areas, such as header, sidebar, and footer.

Composition combines focused pieces

Composition means putting components inside other components. It is React's main reuse mechanism: each piece handles a small responsibility, and a parent arranges the pieces into a feature.

  • Keep leaf components focused.

    A button can own button behavior while a product card owns product presentation.

  • Pass data down.

    The parent provides the values a child needs through props.

  • Pass actions down.

    A function prop lets a child report an interaction without owning the parent's data.

Component purity keeps rendering predictable

A pure component returns the same JSX when its props, state, and context are the same. Rendering should calculate the interface, not change data that existed before the render.

Impure during render

Mutates a variable outside the component, so repeated renders produce different results.

Pure during render

Uses its input to calculate a value without changing anything outside the component.

Local calculation is safe. Creating a new array, object, or variable inside the component does not affect code outside that render. Event handlers may update state because they run in response to an interaction, not while React is rendering.

The design rule: pass information with props, expose flexible space with children, assemble small components through composition, and keep rendering pure.

Check your understanding

  1. What receives the paragraph in <Panel><p>Hello</p></Panel>?
    Show answer

    The children prop receives the paragraph element. Panel can render it with {children}.

  2. Why should a child not change an object it received as a prop?
    Show answer

    Props are read-only inputs. Mutating the object also changes data owned by the parent, making the interface harder to predict. Ask the parent to update it through an event handler instead.

  3. Is calculating const total = price * quantity during render impure?
    Show answer

    No. It only derives a local value from inputs and changes nothing outside the component.
