State Updates in React

Setting state does not change the current render. It asks React to calculate a later render, and React processes queued updates in a predictable order.

State update queues

Every render receives a snapshot of state. Calling a setter such as setScore queues an update, but the score variable in the running event handler remains the value from that render.

Event runsThe handler reads its render's state snapshot.
Updates queueSetter calls request values for the next render.
React rendersThe queue is processed and the UI receives new state.

A setter is a request, not an assignment. If later code in the same handler needs the next value, calculate it in a local variable or use a functional update when it depends on queued state.

Batching groups updates

React waits until the event handler has finished before processing its state updates. This batching avoids an extra render after every setter call and prevents the screen from showing half-finished state.

React does not batch separate intentional interactions into one event. A second click gets its own handler and its own state snapshot. Modern React also batches many updates from promises, timers, and native event handlers when the app uses createRoot.

Functional updates use pending state

When the next value depends on the previous value, pass an updater function to the setter. React puts that function in the queue. During the next render, it calls each updater in order and passes the result to the next one.

Repeats one replacement

Three calls to setCount(count + 1) all calculate from the same snapshot, so they each request the same value.

Builds on the queue

Three calls to setCount(c => c + 1) receive 0, then 1, then 2, producing 3.

Updater functions run while React renders, so keep them pure. Return the next state without changing existing objects, arrays, variables outside the function, or the DOM. In development, Strict Mode may call an updater twice to reveal accidental mutation.

Immutable object updates

Treat objects stored in state as read-only. Mutating an existing object keeps the same reference and changes data that older render snapshots may still rely on. Instead, create a new object and copy the fields that should remain.

Spread syntax is shallow. To change a nested value, copy every object from the changed field back to the top-level state object.

Do not write profile.city = value. Build a new object and pass it to the setter. When state becomes deeply nested and awkward to copy, consider flattening its shape or using a reducer.

Immutable array updates

Arrays in state are objects too, so treat them as read-only. Create a new array with spread syntax, map(), or filter(), then store that array.

  • Add with spread.

    Use [...items, newItem] instead of items.push(newItem).

  • Remove with filter().

    Keep every item whose ID is not the one being removed.

  • Replace with map().

    Return an updated copy for the matching item and return every other item unchanged.

Methods such as push(), pop(), splice(), sort(), and reverse() mutate the original array. For sorting or reversing, copy first: const next = [...items]; next.sort(compareItems); setItems(next);.

Check your understanding

  1. Why does reading state immediately after its setter return the old value?
    Show answer

    The running handler belongs to the current render and sees that render's fixed state snapshot. The setter queues work for a later render rather than changing the local variable.

  2. When should you prefer setCount(current => current + 1)?
    Show answer

    Use a functional update when the next state depends on previous or already queued state. React passes each updater the latest pending value.

  3. How do you update one object inside an array without mutation?
    Show answer

    Use map() to create a new array. For the matching item, return a new object with the changed field; return every other item unchanged.
