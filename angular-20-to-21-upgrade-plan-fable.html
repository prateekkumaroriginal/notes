Angular 20 to 21 upgrade, revised

Move TopFans from Angular 20.3 to 21.2 before the v20 LTS window closes on 2026-11-28. Replace @angular/fire with the Firebase SDK, bump the libraries whose installed release rejects Angular 21, and leave zone.js, NgModules, Karma, and quill alone. Done means the scripts CI actually runs are green, the SSR log is clean, and push notifications work for both a first-time and a returning user.

Branch feature/release-0.0.23/16-17-18-19-20-21, cut from 64a1a3d259. This revision folds in two independent audits of the first draft. Items marked changed are new or corrected. Sources: 21.0.0 release notes, update guide, GHSA-x288-3778-4hhx.

What changed from the first draft

  • .npmrc already has legacy-peer-deps=true. The overrides idea is gone. ng update runs its own peer check and needs --force for core and for Material.
  • CI runs Node 20 with npm 10.8.1, not the Node 24.5 / npm 12 on the dev machine. Phase 0 now checks the CodeBuild Node minor against Angular 21's ^20.19.0 floor.
  • Untracked HTML plans in the repo root block ng update the same way modified files do.
  • The Firebase test now covers a returning user. Today onMessage() only runs when the token changes, so a user with a saved token gets no foreground listener. The rewrite fixes that.
  • Remote Config gets its own isSupported() check. requestFirebaseToken() gets a browser guard.
  • The repo's custom UrlSerializer has a dedicated router change in 21 (#64449). It is on the checklist now.
  • Two missed @HostBinding files, 35 CDK files instead of 25, Font Awesome's svg-core 7 dependency, and ngx-scrollbar's deferral are all named.
  • Phase 5 runs the prerender-all-* scripts that the buildspecs call, not the shorter prerender-qa.

Decisions

Replace @angular/fire with the firebase SDK. The only Angular 21 build is 21.0.0-rc.0, it depends on firebase ^12.4.0, and nothing newer has shipped. The repo uses four SDK functions and three providers. Calling firebase/messaging and firebase/remote-config directly removes the dependency and keeps Firebase at 11.10.0, the version installed today.

Do the Firebase swap first, on Angular 20. If push tokens break after the framework bump, the framework did it.

Use --force on both ng update commands and say why. changed ng update reads installed peerDependencies and refuses when any package rejects the target. @cotufa82/ng-ivs declares Angular 12, @khajegan/ngx-audio-player declares Angular 17 and Material 17, ngx-stripe declares Angular 18. Neither .npmrc nor overrides nor npm 12's packageExtensions affects that check. --force skips the check, not the migrations. It is the same situation the 20 upgrade was in.

Keep zone.js. 46 files touch NgZone. The 21 migration adds provideZoneChangeDetection() to AppModule on its own; that is the only change.

Keep Karma, skip Vitest. No spec files, nothing to run.

Leave ngx-quill 16.2.1 and quill 1.3.7. Peer is @angular/core >=13. ngx-quill 30 needs quill 2, which is its own project.

Upgrade rule. changed Bump a library when its installed release rejects Angular 21 or when a same-major patch exists for 21. Leave libraries with open peer ranges even if a newer major exists. That keeps ngx-scrollbar 9 (17 files use it; 19.1.5 exists with API changes), ngx-image-cropper 6, and ngx-sharebuttons 8 where they are.

Defer ng-ivs, ngx-audio-player, and ngx-stripe. All three already sit outside their declared range and run through the partial-compilation linker. ngx-stripe 21.9.0 would force @stripe/stripe-js to 9.x; the repo is on 3.5.0 and already outside ngx-stripe 18's own >=4 <5 range.

Stay on NgModules. No standalone, ngClass, or ngStyle migrations here.

Firebase: the SDK without AngularFire

Everything Firebase-related is in two files plus the service worker. The public shape of FirebaseService does not change, so its 14 consumers are untouched.

FileChange
package.jsonRemove @angular/fire. Add "firebase": "11.10.0" to dependencies.
src/app/app.module.tsDelete provideFirebaseApp, provideMessaging, provideRemoteConfig and their imports. Initialization moves into the service.
src/app/modules/shared/services/firebase.service.tsReplace inject(Messaging) and the RemoteConfig constructor param with lazy, browser-only getters. Import initializeApp, getApps from firebase/app; getMessaging, getToken, onMessage, isSupported from firebase/messaging; getRemoteConfig, fetchAndActivate, getValue, isSupported from firebase/remote-config. Alias the two isSupported imports.
src/firebase-messaging-sw.jsNo change. Compat 9.6.1 from gstatic, never depended on AngularFire.

Contract the rewritten service must keep

  • Public members unchanged: requestFirebaseToken(), onMessage(), getRemoteConfigValue(), logOutToken(), setConfigToken(), generateFingerprint(), deviceToken, $deviceId, iosPayButtonsConfig.
  • Never touch firebase/messaging or firebase/remote-config on the server. AngularFire returned null there and the && this.remoteConfig check hid it. The raw SDK throws. Guard getRemoteConfigValue() and requestFirebaseToken() with platformService.isBrowser. changed The token path has no guard today; its only caller is header.component.ts:825.
  • Call each product's isSupported() before its get*(). changed Messaging returns false on non-secure origins and some Safari modes. Remote Config returns false when IndexedDB exists but rejects open(), which happens in private browsing.
  • Initialize once: check getApps().length before initializeApp(environment.firebaseConfig). White-label builds swap the config via fileReplacements.
  • Attach the foreground listener on every browser session, not only when the token changes. changed Today onMessage() is called only inside setToken()'s subscribe, and setToken() runs only when the token differs from fc_token in localStorage. A returning user gets no listener. Register the token when it changed; attach onMessage regardless; keep the unsubscribe handle.
  • Wrap the toast call and the iosPayButtonsConfig assignment in NgZone.run(). AngularFire did this for us. Zone.js probably catches the underlying events anyway, but the explicit call costs two lines and removes the question. Leave a comment pointing the future zoneless task at it.
  • Bundle size should be flat or smaller: the same firebase/* chunks were already there, and rxfire plus the AngularFire wrappers drop out.

Open questions and assumptions

  • CodeBuild image. Which image do the four buildspecs run on, and what does its nodejs: 20 resolve to? This decides whether Phase 0 touches the buildspecs.
  • Remote Config during prerender. Assumed not needed. It only drives iOS payment buttons, never part of prerendered marketing HTML. The service becomes browser-only.
  • Returning-user listener. Assumed the current behaviour (no onMessage when the token is unchanged) is a bug, not a product decision. If it was deliberate, say so and the contract changes.
  • Firebase 12. Out of scope. Pinning 11.10.0 keeps the Firebase surface identical to today.
  • PR target. Branch naming suggests this stacks on 16-17-18-19-20. Confirm whether that merges first.

Out of scope

  • Zoneless change detection, OnPush conversions, signal forms.
  • Vitest or any test setup.
  • Standalone components, CommonModule removal, ngClass/ngStyle migrations, inject() migration.
  • Moving the serverless and test targets off @angular-devkit/build-angular. Both builders still ship in 21.2.24. Revisit before 22.
  • platformBrowserDynamic to platformBrowser in main.ts. Deprecated, still works.
  • quill 2, Firebase 12, ngx-stripe 21, ng-ivs, ngx-audio-player, ngx-scrollbar 19, ngx-image-cropper 9, ngx-sharebuttons 17.
  • Angular 22. Needs Node ^22.22.3 || ^24.15.0 and TypeScript 6.0. Separate branch once this lands.
