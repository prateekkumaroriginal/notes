What the tokens fix

ng-bootstrap 20 creates the modal component with options.injector as the parent injector. A token provided there is visible to inject() while field initializers run. input(default) then keeps that value, because these modals are not opened with a template binding.

The old code did modalRef.componentInstance.isModalView = true after open(). That replaces the signal function with a boolean. The next isModalView() throws is not a function. Same failure for loggedInUserData, userType, showMessageArea, priorTipCloseResult, and the livestream preview inputs.

Send Tip now reads SEND_TIP_MODAL_DATA. Checkout and preview modals each have their own token. Routed pages inject with optional: true and fall back to the old defaults, so a normal page visit stays unchanged.

data on the tip dialog is still a decorator @Input(). Minimum tip and monetization can keep assigning componentInstance.data. currencyConversionData is a plain field. Reels still opens the same dialog through the Material bottom sheet and MAT_BOTTOM_SHEET_DATA.

The fundraiser store picker binds modalHeader and apiEndPoint in the template and types the viewChild. Those two are signal inputs, so writing them on the component instance was the same class of bug. Livestream and messages still assign disabledOptionsByTab, which is a decorator @Input().

Three opens still throw

After open() returns, the active livestream screen subscribes to componentInstance.closeModal for order payment, customer information, and shipping options. Those three classes have no closeModal output. The subscription throws before the click handler finishes.

That line is already on the base commit 5449fe850e. It was easy to miss because the signal assignment threw first, on a later change detection. This pull request removes that throw, so execution now reaches closeModal.subscribe. The modal node is already in the document. The handler still errors, and nothing is listening for dismiss.
