Chat cursor pagination

The inbox used to download every conversation and sort them into tabs on the client. It now asks the server for one tab page. History dropped timestamps and started using a cursor. The first history page also returns send permissions, so the extra validation POST is gone.

t3code/explain-chat-api-pagination Jon Snow staging on :4202 6 Oct 2026

What changed

Three files. Query strings and body keys live in messages.constant.ts. The rest is message-container.

BeforeNow
One GET with search_key. The client split rows by featured, broadcast, and empty last message. One GET per open tab. tab=featured|general|broadcast for creators. Fans send tab=all. Always counts=true.
The left list had no next page. Scroll down sends the last cursor. Null cursor stops. A tab change or a new search starts page 1 again.
Tab pills were unread sums of whatever had already loaded. Pills read counts.featured and counts.general. The sidebar number is general + featured + broadcast.
History POST sent timeStamp. Scroll-up was commented out. First page is { groupId, include_validation: true }. Next page is { groupId, cursor }. Older messages prepend and the viewport stays put.
Permissions were a second POST to ChatUserValidation. First history page returns validation. Retry refetches that first page. Broadcast and followers still skip it.

Empty search is omitted, not sent as search_key=. Opening an unread row still zeros that row and subtracts its unread from the stored counts so the pills do not bounce back until the next inbox GET.
