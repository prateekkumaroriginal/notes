Migration

Angular 17 to 18

The working tree is on Angular 18.2 with NgModules, the application builder, and custom Express SSR kept. PrimeNG stays 17. Ship the source hunks below. Do not ship env or prefetch artifacts.

Implementation

Node 20.19.6, TypeScript 5.4.5, and Zone 0.14.10 already met Angular 18. Those were left alone. Angular 18.2 accepts TypeScript 5.4 and 5.5 and rejects 5.6.

ng update @angular/core@18 @angular/cli@18 then @angular/material@18, with 10GB old-space. The application-builder schematic was refused. The HttpClient schematic was refused and reverted if it ran. server.ts was not replaced by CLI output. Hand edits only for what 18 actually broke.

Libraries that publish an Angular 18 line were bumped. PrimeNG, ngx-quill, and ngx-intl-tel-input stayed on the current majors. @khajegan/ngx-audio-player stayed 17.1.0. @cotufa82/ng-ivs stayed as a legacy peer.

Compile used --configuration=development and qa with --prerender=false. Production proof used npm run prerender-all-qa. npm run build-dev was not used; environment.dev.ts is still missing. Docker was not used.

Kept on purpose

  • NgModules. No standalone rewrite. No standalone: false flags (those are v19).
  • @angular-devkit/build-angular:application. Already in angular.json.
  • Custom Express in server.ts. White-label still picked from dist/.
  • HttpClientModule in AppModule and FormSelectComponent. Interceptors still use HTTP_INTERCEPTORS.
  • Hydration off. No provideClientHydration. No ngZoneEventCoalescing.
  • Material 2 with prebuilt indigo-pink.
  • PrimeNG 17.18.15 and saga-blue. PrimeNG 18 dropped that theme and wants providePrimeNG.
  • functions/ and the webpack serverless target untouched. Live path is serve:ssr / S3 prerender.

SSR shell path

Angular 18 writes the client shell as index.csr.html when prerender is off. Prerendered routes still use index.html. Express must prefer the CSR file for installServerDom and CommonEngine.documentFilePath or live SSR serves the wrong document.

+  return join(distFolder, 'index.html');

DOMPurify under esbuild

The Angular 18 esbuild pipeline does not accept the default DOMPurify import. Namespace import plus .default fallback keeps sanitize working on client and server.

diff --git a/src/app/app.component.ts b/src/app/app.component.ts
-import DOMPurify from 'dompurify';
+import * as DOMPurifyNs from 'dompurify';

+type DomPurifySanitize = {
+  sanitize: (dirty: string, cfg: { ALLOWED_TAGS: string[]; ALLOWED_ATTR: string[] }) => string;
+};
+
+const DOMPurify: DomPurifySanitize =
