Review result

I found no regression in this PR. The converted pages keep their route paths, guards, template dependencies, and callback logic. I built the PR commit and requested thirteen URLs from its SSR server. Each returned the expected page or 404 response.

I did not test form submissions, authenticated callbacks, browser hydration, or white-label builds. Those still need release testing.

What changes

The PR changes 42 files, adding 154 lines and removing 3,016. Fifteen public pages now load as standalone components. The PR removes their NgModules and two unused page modules, seventeen module files in total.

  • Informational pages: about, pricing, privacy policy, terms, and help/FAQ.
  • Contact pages: contact-us and contact-v1, including both demo aliases.
  • Callback and utility pages: calendar-connect, shopify-connect, imported-opt-out, unsubscribe-newsletter, unsubscribe-instruction, shortend-url, access-user-account, and not-found.

Routes still load lazily through dynamic imports. They now load the component directly. Both terms URLs, both demo URLs, and the global and link-in-bio wildcards still load the same components.

The PR deletes public/advertise and public/comparison. The live pages use advertisement-home and comparison-page.

Code review

The components import what their templates use

About, pricing, privacy, terms, and help now import RouterLink directly. Their old page modules supplied it through RouterModule. I checked the rendered HTML for all six URLs, including both terms URLs. Every Home link had href="/".

Contact-us imports NgSelectModule for its dropdowns. Contact-v1 imports DynamicFormBuilderModule for its form. SharedModule exports the other form directives and shared UI these pages use. Help keeps FaqComponent and drops CarouselModule, which its template does not use.

Imported-opt-out still imports AlertModalComponent in TypeScript to open its dialog. That import survives the module deletion. Pricing, Calendar, and Shopify compile without CUSTOM_ELEMENTS_SCHEMA.

Contact-us imports · Demo form imports · Help template imports

Routes keep their metadata and guards

The page data strings move into PUBLIC_PAGE_ROUTE_DATA. Contact-us and both demo URLs use the same contact data. Both terms URLs keep the route title. The guards stay on the same routes.

The components also call SeoService. Both terms URLs rendered "Terms of Service - TopFan" in my SSR check, which differs from the route title string. The PR preserves the route title, but that string alone does not determine the rendered title.

App route configuration · Public page metadata

Components read parameters from their own route

None of the converted components reads a parent ActivatedRoute or depends on the removed empty child route. Calendar, Shopify, account access, opt-out, and unsubscribe read query parameters from the activated route. Short links read the named shortend-url path parameter. Removing the empty child route leaves those values available on the page route.

Shortend-url and access-user-account have empty templates. Their application services use providedIn: 'root', so Angular can inject them without SharedModule. None of the fifteen deleted page modules declared a custom provider that needs to move.

Short-link parameter access · Account-access dependencies

The 404 routes return 404

NotFoundComponent still sets HTTP status 404 and adds robots noindex. I checked /not-found, an unknown multi-segment URL, and the link-in-bio wildcard. All returned 404 and rendered NotFoundComponent.

404 status and SEO · Link-in-bio wildcard

Nothing imports the two deleted pages

I found no remaining imports or class references to AdvertiseModule, AdveriseComponent, ComparisonModule, ComparisonComponent, or their deleted directories. One unused app-advertise CSS rule remains. It can be removed separately.
