What's left

No route loads SharedModule, and with PR 10841 no feature NgModule is left. Optional leftovers, and what I would do with each, are in leftovers after the SharedModule work.

What the steps taught

  • The first count missed standalone components that still import SharedModule. In step 3, /monetize kept loading it through the text editor, its AI modal and the post price dialog. Step 4 was meant to be import swaps only and needed nine conversions. The table above now counts those files too.
  • My conversion script moved a declaration to imports only when a comma followed it, so it missed the last entry twice. That's fixed, and it now works on any NgModule file.
  • A module's CUSTOM_ELEMENTS_SCHEMA can hide dead bindings. Portfolio's hid four [infoIconSize] bindings on a component with no such input, and edit preference's hid a [socialHandles] binding. Dashboard's hid a [coverImage] binding on the video player.
  • A module's providers need a new home when the module goes. Edit preference provided DatePipe for one page, so that page provides it now. Dashboard gave itself its own DashboardModuleService, which holds state, so its providers moved to its top-level route. That keeps a separate instance, like the lazy module did.
  • Providers the old module got from an imported module count too. Dashboard got isPostCollaboratorPipe from SharedModule, and that pipe reaches DashboardModuleService through MyProfile. So it went on the dashboard route as well.
  • A diff that ignores too much can hide a regression. The form builder component lost five field components on the first try, because the diff filter skipped more than the one directive it was meant to. The diff script now ignores only that directive, and a rerun on PR 10840 found nothing new.
  • An NgModule that nothing imports drops out of the compile. Once dashboard stopped importing SharedModule, its remaining declarations compiled with no template scope. So they had to become standalone first.
  • Importing a whole feature module into another also imports its routes. Portfolio's 26 routes were reachable under /dashboard until step 6.
  • The test account is a white-label creator, so creator pages only open on a white-label build. The main site sends creators to /edit-preference/whitelabel. Logged-in checks from step 3 on ran on a white-label build.
  • /messages sometimes throws "Cannot read properties of undefined" when the QA API is slow. It happens on base too.
