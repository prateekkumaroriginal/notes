PR 10829: three more pages without NgModules

This finishes the single-component feature modules. /advertise, /global/category-creator-listing, and the marketing-pro pages now load their components without a module and a routing module in between. Six files are gone, and nothing a user sees should change.

topfan/TopFansLite-WebFrontend#10829 base hotfix/release-0.0.23/21-code-refactors 12 files, +26 −124

What changed

Before this PR, each page needed three files. A component declared with standalone: false, an NgModule that declared it, and a routing module with a single route. Now the component lists its own imports, and the router loads it directly.

PageURLsNow loads withComponent imports
advertisement-home /advertise loadComponent CommonModule, SharedModule, FaqComponent, ButtonComponent
global /global/category-creator-listing loadChildren with global.routes.ts CommonModule, SharedModule
marketing-pro-page /pro, /refer, /apps/* loadComponent, generated CommonModule, MarketingPageSharedModule, FaqComponent

advertisement-home dropped six unused imports

Its module imported form, select, modal, accordion, multiselect, and video modules. The template uses none of them. It uses buttons, the FAQ, a circle icon, and two directives from SharedModule.

If the template had needed one of the dropped modules, the build would have failed. Standalone components don't get CUSTOM_ELEMENTS_SCHEMA from anywhere, so an unknown tag is a compile error. The build passed.

global kept a routes file

The other pages had a child route with an empty path, so the component could move up to the parent route. global's child route has a real path, category-creator-listing. The app route stays global with loadChildren, and the child moved into a plain Routes array. link-in-bio-fan-preview did the same in PR 10826.

- import('./modules/global/global.module').then((m) => m.GlobalModule)
+ import('./modules/global/global.routes').then((m) => m.GLOBAL_ROUTES)

The module also imported RouterModule, but the template has no router directives, so the component doesn't import it.

Marketing-pro routes are generated

scripts/prefetch-marketing-pages.mjs runs before every QA, staging, and prod build. It fetches published pro pages and writes marketing-pro-page-routes.generated.ts. Pro slugs can be nested, like apps/music-artists-fan-club, so the script builds a tree. Parent segments get children, and each leaf loads the page. The PR changes the leaf template in the script and the committed generated file together.

I found a stale file along the way. The committed routes list two /apps/* pages, but the committed data file only has apps/music-band-fan-club. So on a local build without a fresh prefetch, the pro pages load the component, find no data, and redirect to not-found. This was already true before the PR. Deployed builds regenerate both files, so they don't hit it.

What stayed the same

  • Route data. The marketing-pro component finds marketingProSlug by walking up route.parent. The data now sits on the component's own route, one step closer.
  • Case-insensitive URLs. The apps parent has children, so it matches a prefix. Each leaf has no children array and must match the rest of the URL. That was true for the old loadChildren leaves too.
  • The category listing's data. The search bar puts the chosen category in DataService, then navigates. DataService is a root singleton with a BehaviorSubject, so the standalone component reads the same instance.
  • Initial bundle. 12.30 MB on both the base branch and this branch.
