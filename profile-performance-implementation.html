Banner priority

The optimization directive already knew how to set fetchpriority="high" and eager loading. The profile banner never asked for it, and it shipped loading="lazy", which blocked the directive from flipping loading. I turned priority on and dropped the lazy attribute. The subscription-modal copy of the banner is still lazy. That image is not LCP.

Header logo sizing

PR 10977 asked for a 290×32 WebP. That is a 9:1 box. Tenant logos are not all 9:1, and the CSS already does object-fit: contain at 32px tall with a 290px max. Forcing both width and height on the image handler would squash the file before CSS could save it.

I request width only, 290 or 240 for the pro header, with fit="contain". WebP is already the default. I also set [priority]="true" because this logo was already loading="eager" and it is LCP on marketing chrome.

header-layout.component.html

[originalUrl]="logoUrl" [width]="isProPageLogo() ? CONST.LOGO.REQUEST_PRO_WIDTH : CONST.LOGO.REQUEST_WIDTH" [fit]="CONST.LOGO.FIT" [priority]="true"

S3 cache headers

Every rclone copy used Cache-Control: public,max-age=31536000,immutable, including index.html and prerendered HTML. Express never sees those objects. A checksum skip also leaves old metadata on unchanged HTML, so a deploy can look like it did nothing.

deployment_script/rclone-upload-dist.sh now does three passes:

  1. Non-HTML, non-manifest files: immutable, checksum skip as before.
  2. HTML: max-age=0,must-revalidate, --ignore-times so existing objects get new headers.
  3. ngsw.json, worker scripts, and manifest.webmanifest: same revalidate treatment.

TopFans still only excludes explore/**. Tenant scripts set RCLONE_TENANT_EXCLUDES=1 so splash, favicon, and sitemap stay off this path the way they already were. I did not hand-edit generated white-label projects.

After the first deploy, open an existing index.html in the bucket and read Cache-Control. If it still says immutable, the helper did not run, or CloudFront is holding the old object.

Defer sidebar and welcome video

Modals already defer on idle. Sidebar and welcome video did not. Both now defer on viewport and prefetch on idle.

Angular still needs the components in the parent imports array. Removing them is how you get a build failure with a selector still in the template. I left ProfileSidebarComponent and WelcomeVideoPostComponent declared.

The welcome-video placeholder is a 16:9 block in --configSecondaryBgColor, so the feed does not collapse while the chunk loads. The sidebar placeholder reuses app-right-sidebar-skeleton, the same skeleton the loading path already shows.

Visible profile SSR

The whole profile shell sat behind cs.isBrowser && isBasicProfileLoaded. The server rendered a skeleton and a hidden name/bio. First paint in the document was empty chrome.

Two things had to move together. Un-gating the template without consuming TransferState would refetch on the client and mismatch hydration. Using PRERENDERED on the server and REFRESH_EVERY_N in the browser, which is what PR 10977 did, never reads the TransferState entry. Only PRERENDERED does.

The first request is now always CacheTypes.PRERENDERED. If TransferState has the payload, of(data) emits in the same turn as subscribe, so isBasicProfileLoaded is true before the first client render. If the visitor is logged in and we just consumed transferred anonymous data, a second REFRESH_EVERY_N call updates follow and privacy. That second call does not wipe the feed unless privacy actually flipped. Feed loading, ads, and fetchPostsWithSkyscraperAds stay as service cleanup left them.

profile.component.ts, abbreviated

this.apiCacheService.get(APIENDPOINT.user(userId), CacheTypes.REFRESH_EVERY_N) const hadTransferredProfile = this.transferState.hasKey(stateKey); this.apiCacheService.get(endpoint, CacheTypes.PRERENDERED) // ... handleUserProfileResponse(res) // if hadTransferredProfile && browser && authenticated // get(REFRESH_EVERY_N) then handleUserProfileResponse(fresh, false)

The hidden prerender name/bio block only renders when the profile has not loaded yet. Once first-paint content is in the document, duplicating it is noise.
