What gets deleted

  • ProfileDetailComponent, SubscriptionSelectModalComponent, SubscriptionPlanDurationModalComponent and the old typeahead SearchBarComponent.
  • SeoLandingComponent, SeoLandingCreatorCardComponent and SelectInterestsAccordionComponent.
  • The portfolio, feed-content and event-ticket store-item components, plus their private constants and portfolio interface.

The PR deletes 33 files and edits three. The edited files remove a commented profile search block, its unused fields and methods, and two store-item CSS selectors.

Code review

No active component loses a dependency

I searched the remaining application TypeScript, templates, SCSS and JSON for every deleted component class, selector, exported constant and interface. There are no remaining references. All ten component classes are also absent from the saved base compiler output.

Fresh Angular compilation still emits 646 components. Their resolved template dependency lists match the base exactly. This checks the active component graph as well as the source references.

The live search bar stays

The deleted SearchBarComponent uses app-search-bar-typeahead. The active search component in src/app/components/search-bar/ uses app-search-bar and remains unchanged. Wallet, resources, insights and other pages still use it.

The profile's removed typeahead markup was entirely inside an HTML comment. After stripping comments and normalizing whitespace, the old and new profile templates match. See the retained search component.

The profile cleanup has no remaining caller

The removed isSearchBarOpen and searchClass fields, addClass and closeSearch methods, and Renderer2 and ElementRef constructor parameters belonged to the commented search block. The remaining profile code and template do not reference them.

ElementRef remains imported because other profile view queries still use its type. There is no change to the active profile routes, subscriptions or payment flow.

Shared types and the current store card remain

The PR keeps seo-landing.model.ts. Its Creator type still has three consumers, including the featured-creator picker and cover-page editor.

StoreLayoutItemCardComponent remains imported by both the store-item and store-items-grid layouts. The store-item template already uses that card for non-merchandise items. Merchandise still uses the share-details preview. The removed feed-content and portfolio selectors have no matching elements in the remaining source.

See the retained card import and the retained model.

One existing lint warning remains

ESLint reports that ProfileComponent defines ngOnChanges without implementing OnChanges. I reproduced the same warning on the base. There are no lint errors in my run, and this PR does not introduce the warning.
