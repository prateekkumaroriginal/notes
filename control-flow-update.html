Control Flow Update

Replace legacy Angular template directives with @if, @for, and @switch using the official schematic, targeted manual fixes, and build and behavior validation.

Implementation sequence

  1. Record the baseline

    Preserve unrelated working-tree changes. Inventory external and inline templates, tracking functions, shared template references, and direct directive imports or queries. Record existing main and white-label build failures before migration.

  2. Run Angular's official schematic

    Preview and apply the control flow migration using the repository's installed Angular CLI. Review migration diagnostics and the changed-file list. Keep routing, styling, module structure, and business logic outside this change.

  3. Review and repair the generated changes

    Resolve remaining directives and template errors. Preserve aliases, loop context variables, template reuse, and tracking intent. Remove obsolete imports only after checking their uses; retain CommonModule where other directives or pipes need it.

  4. Validate builds and user behavior

    Build the main and generated white-label projects with the required 10 GB memory setting. Use manual behavior checks for the flows below and verify representative SSR output and hydration where enabled. Karma is configured, but there are currently no .spec.ts or .test.ts files under src; do not assume existing automated test coverage.

  5. Close with evidence

    Repeat the legacy-syntax scan, classify remaining matches, and review the final diff. Record build results, tested flows, migration warnings, and unresolved failures.

Where to start reviewing

Prioritize these groups when reviewing the generated changes:

  • 135 conditional usages with else or then.
  • 85 conditional as aliases.
  • 84 loops with trackBy.
  • 238 loops mentioning index, first, or last.
  • 15 files using ngSwitch.

These are current text-scan counts and may include comments. Groups overlap and mix occurrences with files, so they are review priorities, not a count of unique locations. Refresh the inventory before migration and still review the overall diff.

Where manual review matters

AreaReview requirement
Loop trackingPreserve existing trackBy semantics. Avoid switching changing lists to index tracking without checking the consequences. Verify insertion, removal, reorder, and item replacement.
View reuse@for can retain a view when a tracked property changes on the same object, as documented by Angular. Separately, changing tracking from object identity to an ID can reuse views for replacement objects with that ID. Preserve tracking intent and check state where remounting previously mattered.
Conditional templatesCheck aliases, nested branches, and shared ng-template references. Preserve templates still used by outlets, queries, or other consumers.
Switches and wrappersVerify cases, defaults, and content outside cases. Check wrappers whose removal could affect styling or content projection.
Imports and queriesReview TypeScript references to the old directives. Compilation may not expose a query that now returns no directive.
