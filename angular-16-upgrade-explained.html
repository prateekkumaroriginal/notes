Angular 16 upgrade explained

The application moved from Angular 15.2 to 16.2 as a controlled first step. Framework packages, build tools, SSR, and Angular-dependent UI libraries now agree on one compatible version set. The final Angular update-guide cleanup is also applied.

1. What the upgrade does

The change keeps the existing NgModule application and Universal SSR architecture. It updates the version contract around them and applies the compatibility edits required by Angular 16.

RuntimePin Angular, RxJS, TypeScript, Zone.js, and Node.js.
LibrariesAlign Material, NgRx, PrimeNG, Bootstrap, forms, media, and Stripe packages.
MigrationsApply Angular's router, CLI, and module cleanup migrations.
CompatibilityUpdate SSR imports and APIs changed by newer UI libraries.
ProofCompile development, optimized production, and SSR bundles.

No product feature or route was intentionally redesigned. The work changes framework contracts and build behavior while preserving the application's current structure.

3. Source changes required by Angular 16

Router guard interfaces removed

Angular 15.2 deprecated class interfaces such as CanActivate and CanDeactivate. The migration removes those imports and implements clauses. Existing canActivate and canDeactivate methods remain, so route behavior stays structurally compatible.

Obsolete entry component metadata removed

entryComponents was deleted from SharedModule. Ivy discovers dynamically created components without that NgModule list.

SSR Zone.js import updated

zone.js/dist/zone-node became zone.js/node in both server.ts and serverless.ts. The old deep import is not exported by Zone.js 0.13.

PrimeNG removal API updated

The custom multiselect calls removeOption(item, event) instead of the removed removeChip(item, event) method.

ngx-mask registration updated

The wallet module imports standalone mask directive and pipe classes, then registers provideNgxMask(). This replaces the older NgxMaskModule.forRoot() pattern.

Unused View Engine package removed

ngx-drag-and-drop-lists and its module import were removed. Messages already uses Angular CDK drag-drop, and Angular 16 no longer runs the old compatibility compiler.

Transfer state imports moved

TransferState and makeStateKey now come from @angular/core in the platform service and both cache services. Angular 16 moved these public APIs out of @angular/platform-browser.

Server transition wrapper removed

BrowserModule.withServerTransition({ appId: 'serverApp' }) became BrowserModule. Each white-label site is a separate build, so this application does not need an APP_ID to distinguish multiple Angular applications on one page.

Last guard interface removed

WhitelabelSiteOnlyGuard no longer imports or implements the deprecated CanActivate interface. Its canActivate() method and routing behavior are unchanged.

The two white-label generated constant files only received new generation timestamps. Their exported data did not change.

4. Build and developer tooling changes

  • angular.json now records explicit buildOptimizer values for server and serverless configurations. Optimized targets use true; development uses false.
  • tsconfig.json points typeRoots to node_modules/@types, allowing TypeScript 5.1 to resolve Node declarations during browser and SSR compilation.
  • Angular ESLint builder, schematics, and template parser packages were added. Two invalid trailing commas were removed from .eslintrc.json, so the lint command now reaches source validation.
  • package-lock.json was regenerated to lock the Angular 16-compatible dependency tree.
