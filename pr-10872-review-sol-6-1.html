The appearance fix closes the last finding

The iframe query is now optional. During ngOnInit, applying the default palette can call the preview sender before Angular has finished rendering the view. An optional query returns an absent value at that point, allowing the sender to return safely.

The sender now checks cs.isBrowser first. It then reads the query and returns when the iframe or its content window is missing. This handles server rendering, an unavailable user ID, and the first initialization pass.

readonly previewIframe =
  viewChild<ElementRef<HTMLIFrameElement>>('previewIframe');

sendPreviewMessage(): void {
  if (!this.cs.isBrowser) {
    return;
  }

  const previewIframe = this.previewIframe();
  if (!previewIframe?.nativeElement?.contentWindow) {
    return;
  }

  // The existing configuration and postMessage follow.
}

The iframe remains conditional on userId, and its load handler still calls onIframeLoad. That callback sends the current configuration after the preview is ready. Skipping the early send therefore preserves the existing delivery path.

I checked every previewIframe reference in the updated component. The only query read is inside this guarded sender. The final commit changes no templates, dependencies, or routing.
