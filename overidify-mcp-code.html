The shared contract

mcp-protocol.ts defines every message that crosses the native port. It imports nothing from Chrome or Node, so the extension build and the helper build can both use it. The types make the bridge explicit: the extension sends start once and then result messages, and the helper sends status, call, and chunk messages.

src/lib/mcp-protocol.ts 
export type ExtensionToHostMessage =
  | { type: 'start'; protocol: number; port: number; token: string; version: string; instructions: string; tools: McpToolDefinition[] }
  | { type: 'result'; id: number; result: McpToolResult }

export type HostToExtensionMessage =
  | { type: 'status'; protocol: number; state: 'listening'; url: string }
  | { type: 'status'; protocol: number; state: 'error'; message: string }
  | { type: 'call'; id: number; name: string; arguments: Record<string, unknown> }
  | { type: 'chunk'; id: number; index: number; total: number; data: string }

The start message carries the tool definitions. The helper never has its own copy of them, so changing a tool only needs an extension update.

Messages over 1 MB

Chrome drops any message from a native program larger than 1 MB, and a mock body can be bigger. The helper measures the real UTF-8 size before sending. Anything too large becomes a series of chunk messages of 256K characters. Even at three bytes per character, each chunk stays under the limit.

src/lib/mcp-protocol.ts 
// Chrome rejects host-to-extension messages over 1 MB. Split larger ones into
// chunks that stay below it even when every character needs 3 UTF-8 bytes.
const NATIVE_MESSAGE_LIMIT = 1024 * 1024 - 1024
export const NATIVE_CHUNK_SIZE = 256 * 1024

export function splitNativeMessage(message: HostToExtensionMessage, id: number, size = NATIVE_CHUNK_SIZE): HostToExtensionMessage[] {
  const text = JSON.stringify(message)
  if (new TextEncoder().encode(text).length <= NATIVE_MESSAGE_LIMIT) return [message]
  const total = Math.ceil(text.length / size)
  return Array.from({ length: total }, (_, index) => ({
    type: 'chunk' as const, id, index, total, data: text.slice(index * size, (index + 1) * size),
  }))
}

The service worker puts the pieces back together by call ID and only acts once every piece has arrived.

src/lib/mcp-protocol.ts 
export function createChunkAssembler() {
  const pending = new Map<number, string[]>()
  return (chunk: Extract<HostToExtensionMessage, { type: 'chunk' }>): unknown => {
    const parts = pending.get(chunk.id) ?? []
    parts[chunk.index] = chunk.data
    pending.set(chunk.id, parts)
    if (parts.filter(part => part !== undefined).length < chunk.total) return undefined
    pending.delete(chunk.id)
    return JSON.parse(parts.join(''))
  }
}

Calling a tool

callMcpTool() is the single entry point. It parses the arguments, runs the tool, and always returns an MCP result, never a thrown error. Expected problems use ToolError and reach the agent as written. Anything unexpected gets a short prefix so the agent knows it wasn't its fault.

src/lib/mcp-tools.ts 
class ToolError extends Error {}
// zod/mini omits default messages. Agents need them to correct their arguments.
const ARGUMENT_ERRORS = z.locales.en().localeError

export async function callMcpTool(name: string, args: unknown, deps: McpToolDeps): Promise<McpToolResult> {
  try {
    if (!Object.hasOwn(RUN, name)) throw new ToolError(`Unknown tool: ${name}.`)
    const tool = RUN[name as ToolName]
    const parsed = tool.input.safeParse(args ?? {}, { error: ARGUMENT_ERRORS })
    if (!parsed.success) throw new ToolError(`Invalid arguments. ${formatIssues(parsed.error.issues)}`)
    const result = await (tool.run as (input: unknown, deps: McpToolDeps) => Promise<Record<string, unknown>>)(parsed.data, deps)
    return { content: [{ type: 'text', text: JSON.stringify(result, null, 2) }], structuredContent: result }
  } catch (error) {
    const message = error instanceof ToolError ? error.message : `Overidify could not complete this request. ${error instanceof Error ? error.message : String(error)}`
    return { content: [{ type: 'text', text: message }], isError: true }
  }
}

The zod/mini build ships without error messages to stay small. Without the English locale, every argument error would read "Invalid input", which gives an agent nothing to fix.

Building a rule

After the arguments pass, the tool builds a rule draft and checks it with the same draft schemas the Settings forms use. It then normalizes it the same way: trimmed names, cleaned website lists, and cleaned headers. Error paths are renamed from internal field names to the tool's names, so url becomes websites.

src/lib/mcp-tools.ts 
function buildRequestHeaderRule(draft: Omit<HeaderRule, 'order'> | Omit<SwitchRule, 'order'>, order: number): RequestHeaderRule {
  if (draft.kind === 'header-rule') {
    validate(HeaderRuleDraftSchema, draft)
    return { ...draft, name: draft.name.trim(), url: normalizeWebsiteScope(draft.url), headers: sanitizeHeaders(draft.headers), order }
  }
  validate(SwitchRuleDraftSchema, draft)
  return {
    ...draft, name: draft.name.trim(), url: normalizeWebsiteScope(draft.url), order,
    options: draft.options.map(option => ({ ...option, name: option.name.trim(), headers: sanitizeHeaders(option.headers) })),
  }
}

const FIELD_NAMES: Record<string, string> = { url: 'websites', key: 'name' }

Saving and activating

Every write goes through save(). It reads, changes, and writes rules in one locked step, normalizes both rule lists like the Settings page does, then activates the result and reports what happened.

src/lib/mcp-tools.ts 
async function save(deps: McpToolDeps, update: (rules: RuleCollection) => { rules: RuleCollection; rule?: TransferRule; result?: Record<string, unknown> }) {
  const saved = await deps.updateRules(rules => {
    const next = update(rules)
    return {
      rules: {
        requestHeaderRules: normalizeRequestHeaderRules(next.rules.requestHeaderRules),
        networkRules: normalizeNetworkRules(next.rules.networkRules),
      },
      result: next,
    }
  })
  const activation = await deps.activate().catch((error: unknown) => ({
    ok: false, reloadTabIds: [], error: error instanceof Error ? error.message : String(error),
  }))
  return {
    ...saved.rule ? { rule: viewRule(saved.rule, true) } : {},
    ...saved.result,
    activation: activation.ok
      ? activation.reloadTabIds.length
        ? { applied: true, note: `Saved. Reload ${activation.reloadTabIds.length} matching website tab(s) to apply the latest Network Rules.` }
        : { applied: true }
      : { applied: false, note: `Saved, but Overidify did not confirm the change is active. ${activation.error ?? ''}`.trim() },
  }
}

The lock lives in updateSavedRules(). It holds both storage locks for the whole read-modify-write, so an agent and an open Settings tab can't overwrite each other's changes.

src/lib/rule-transfer-storage.ts 
export async function updateSavedRules<T>(update: (rules: RuleCollection) => { rules: RuleCollection; result: T }): Promise<T> {
  return withRuleStorageLocks(async () => {
    const [requestHeaderRules, networkRules] = await Promise.all([getRequestHeaderRules(), getNetworkRules()])
    const next = update({ requestHeaderRules, networkRules })
    await persistRules(next.rules)
    return next.result
  })
}

The service worker bridge

startMcpBridge() runs when the service worker starts, whenever the MCP settings change, and when the Agents page asks it to reconnect. Each attempt closes the old port, reads the settings, and asks Chrome to start the helper.

src/background/mcp.ts 
// A quiet attempt keeps the current error visible instead of flashing Starting while the page polls for setup.
async function connect(quiet = false) {
  stop()
  const settings = await getMcpSettings()
  if (!settings.enabled || !settings.token) return setStatus({ state: 'off' })
  if (!quiet) await setStatus({ state: 'starting' })
  let port: chrome.runtime.Port
  try {
    // The open native port also keeps this worker alive while MCP is enabled.
    port = chrome.runtime.connectNative(MCP_HOST_NAME)
  } catch (error) {
    return setStatus({ state: 'error', message: `${error instanceof Error ? error.message : String(error)} ${SETUP_HINT}`, setupNeeded: true })
  }

The listeners turn Chrome's errors into statuses. "Not found" and "forbidden" mean the helper isn't registered, so the page shows the setup steps. A protocol mismatch means the installed helper is from an older version.

  if (!message) return
  if (message.type === 'status') {
    if (message.protocol !== MCP_BRIDGE_PROTOCOL) {

    } else if (message.state === 'error') fail({ state: 'error', message: message.message })
    else if (host === port) void setStatus({ state: 'running', url: message.url })

Activating from inside the worker

The Settings page activates rules by sending a message to the worker. Tool calls already run in the worker, and chrome.runtime.sendMessage never reaches its own sender. So index.ts passes in an activation function that calls the header sync and the network sync directly.

src/background/index.ts 
// Rule changes made over MCP happen in this worker, so activate them directly.
startMcpBridge(async () => {
  const [headers, network] = await Promise.allSettled([queueSync(), syncNetworkRules()])
  const errors = [headers, network].flatMap(result => result.status === 'rejected'
    ? [result.reason instanceof Error ? result.reason.message : String(result.reason)] : [])
  return {
    ok: errors.length === 0,
    reloadTabIds: network.status === 'fulfilled' ? network.value : [],
    error: errors.length ? errors.join(' ') : undefined,
  }
})

Settings and status

The switch, port, and token live in chrome.storage.local. The status lives in chrome.storage.session, because it only describes the current browser session. Saving settings always leaves a token in place, so the server can never start without one.

src/lib/mcp-settings.ts 
// Enabling always leaves a token in place, so the endpoint is never unauthenticated.
export async function updateMcpSettings(update: Partial<McpSettings>): Promise<McpSettings> {
  return navigator.locks.request(MCP_SETTINGS_KEY, async () => {
    const next = { ...await getMcpSettings(), ...update }
    if (!isValidMcpPort(next.port)) throw new Error('Use a port from 1024 to 65535.')
    if (!next.token) next.token = createMcpToken()
    await chrome.storage.local.set({ [MCP_SETTINGS_KEY]: next })
    return next
  })
}

The Node helper

The helper is a relay. It reads framed messages from stdin, writes framed messages to stdout, and serves HTTP. Framing is a 4-byte length followed by JSON, and the reader keeps a buffer because a pipe can split a message across reads.

mcp-host/native-messaging.ts 
// Chrome frames each message as a 32-bit native-endian length followed by UTF-8 JSON.
export function encodeNativeMessage(message: unknown): Buffer {
  const body = Buffer.from(JSON.stringify(message), 'utf8')
  const header = Buffer.alloc(4)
  header.writeUInt32LE(body.length)
  return Buffer.concat([header, body])
}

export function readNativeMessages(input: Readable, onMessage: (message: unknown) => void): void {
  let buffered = Buffer.alloc(0)
  input.on('data', (chunk: Buffer) => {
    buffered = Buffer.concat([buffered, chunk])
    while (buffered.length >= 4) {
      const length = buffered.readUInt32LE(0)
      if (buffered.length < 4 + length) break
      const body = buffered.subarray(4, 4 + length)
      buffered = buffered.subarray(4 + length)
      onMessage(JSON.parse(body.toString('utf8')))
    }
  })
}

When the start message arrives, the helper checks the protocol number and starts listening on 127.0.0.1. Errors such as a port already in use go back to the extension as a status, which the Agents page shows.

Each tool call gets an ID and waits in a map for its result, with a 60-second limit. When the extension disconnects, Chrome closes stdin and the helper exits.

mcp-host/main.ts 
function callTool(name: string, args: Record<string, unknown>): Promise<McpToolResult> {
  return new Promise(resolve => {
    const id = nextId++
    const timer = setTimeout(() => {
      pending.delete(id)
      resolve({ isError: true, content: [{ type: 'text', text: 'Overidify did not respond in time. Check that the browser is running, then try again.' }] })
    }, CALL_TIMEOUT_MS)
    pending.set(id, result => { pending.delete(id); clearTimeout(timer); resolve(result) })
    send({ type: 'call', id, name, arguments: args })
  })
}

readNativeMessages(process.stdin, raw => {
  const message = raw as ExtensionToHostMessage
  if (message.type === 'start') start(message)
  else if (message.type === 'result') pending.get(message.id)?.(message.result)
})
// Chrome closes stdin when the extension disconnects or the browser exits.
process.stdin.on('end', () => process.exit(0))

The HTTP endpoint

The endpoint implements what tools need from Streamable HTTP, without the MCP SDK, so the helper has no dependencies and builds to one 8 KB file. Every request passes the same checks before any JSON is parsed.

mcp-host/server.ts 
// Reject DNS-rebound names and browser pages. Agents connect without an Origin.
const hostname = (request.headers.host ?? '').replace(/:\d+$/, '').toLowerCase()
if (!LOOPBACK_HOSTS.has(hostname)) return sendText(response, 403, 'Forbidden host.')
if (request.headers.origin !== undefined) return sendText(response, 403, 'Browser requests are not allowed.')
if (!isAuthorized(request.headers.authorization, options.token)) {
  response.setHeader('WWW-Authenticate', 'Bearer realm="overidify"')
  return sendText(response, 401, 'Missing or invalid bearer token. Copy the connection settings from Overidify.')
}

function isAuthorized(header: string | undefined, token: string): boolean {
  const digest = (value: string) => createHash('sha256').update(value).digest()
  return Boolean(token) && timingSafeEqual(digest(header ?? ''), digest(`Bearer ${token}`))
}

Tokens are compared as SHA-256 digests with timingSafeEqual, which needs equal-length inputs and takes the same time whether the token is right or wrong. After the checks come the method, the protocol version header, the content type, and a 32 MiB body limit.

JSON-RPC

Each message in a request, or each message in a batch, goes through one switch. Notifications have no id and get no reply, and a request that contains only notifications gets 202.

mcp-host/server.ts 
// Notifications and responses to server requests need no reply.
if (typeof message.method !== 'string' || !('id' in message)) return null

switch (message.method) {
  case 'initialize': {
    const requested = params.protocolVersion
    return ok({
      protocolVersion: typeof requested === 'string' && SUPPORTED_PROTOCOL_VERSIONS.includes(requested) ? requested : SUPPORTED_PROTOCOL_VERSIONS[0],
      capabilities: { tools: { listChanged: false } },
      serverInfo: { name: 'overidify', title: 'Overidify', version: options.version },
      instructions: options.instructions,
    })
  }
  case 'ping':
    return ok({})
  case 'tools/list':
    return ok({ tools: options.tools })
  case 'tools/call': {
    const name = params.name
    if (typeof name !== 'string' || !options.tools.some(tool => tool.name === name)) return fail(-32602, `Unknown tool: ${String(name)}.`)
    if (params.arguments !== undefined && !isRecord(params.arguments)) return fail(-32602, 'Tool arguments must be an object.')
    return ok(await options.callTool(name, params.arguments ?? {}))
  }
  default:
    return fail(-32601, `Method not found: ${message.method}.`)
}

The installer copies the helper to a user data folder and writes a small launcher. Chrome starts native programs without your shell's PATH, so the launcher calls the exact Node binary that ran setup, quoted for paths with spaces or apostrophes.

mcp-host/install.ts 
const node = options.nodePath ?? process.execPath

else {
  const quote = (value: string) => `'${value.replaceAll("'", `'\\''`)}'`

  chmodSync(wrapper, 0o755)
}

It then writes a host manifest for each browser profile it finds, or registry keys on Windows, allowing only Overidify's extension IDs. IDs from earlier runs are merged in.

Connecting without Retry

While the helper is missing, the Agents page asks the worker for a quiet reconnect every two seconds. A quiet attempt doesn't change the status to "Starting", so the error message stays steady until the helper starts.

src/options/McpSettings.tsx 
// While the helper is missing, keep checking so setup run in a terminal (or by an agent) connects without clicking Retry.
const setupNeeded = status.state === 'error' && status.setupNeeded === true
useEffect(() => {
  if (!setupNeeded) return
  const timer = setInterval(() => { void chrome.runtime.sendMessage({ type: 'mcp-reconnect', quiet: true }) }, 2000)
  return () => clearInterval(timer)
}, [setupNeeded])

The build

The helper and installer are built during the normal extension build. A small Vite plugin runs a second, Node-targeted build for each entry and emits the result into the extension package as mcp/host.mjs and mcp/install.mjs.

vite.config.ts 
function mcpHostBundle(): Plugin {
  return {
    name: 'overidify-mcp-host-bundle',
    apply: 'build',
    async generateBundle() {
      for (const [entry, fileName] of [['main.ts', 'mcp/host.mjs'], ['install.ts', 'mcp/install.mjs']]) {
        const result = await build({
          configFile: false, publicDir: false, logLevel: 'error',
          build: {
            write: false, target: 'node20', ssr: fileURLToPath(new URL(`./mcp-host/${entry}`, import.meta.url)),
            rollupOptions: { output: { format: 'es' } },
          },
        })
        // … take the generated chunk and emit it into the extension package
        this.emitFile({ type: 'asset', fileName, source: chunk.code })
      }
    },
  }
}
